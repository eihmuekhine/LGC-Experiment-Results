Change D8: CGBA accounting fix (contract v1.4, commit 8f9d52f).
  Two evaluation-only corrections to adapters/run_cgba.py, discovered and verified in B3b:
  (a) FAITHFUL MODEL. The normalised tensor now goes straight into the raw un-normalised
      ResNet-50, exactly as the official drivers (Non_targeted_attack.py:42,84-88 /
      Targeted_attack.py:43,94-98). The old UnnormalizeVictim wrapper un-normalised then let the
      victim re-normalise; that float32 double-normalisation round-trip (max |x_n -
      ((x_n*sd+mu)-mu)/sd| = 2.384e-07 at x0) flips a top-1 decision near the boundary (observed
      at query ~102) and diverges the attack. B3b T2: ratio (old / faithful) reached 0.679 (NT)
      and 1.172 (T) by 10k queries -- far outside the G3 band [0.90, 1.10].
  (b) BOUNDARY-WALK QUERY COUNT. A PatchedProposedAttack subclass overrides go_to_boundary_CGBA
      and go_to_boundary_CGBA_H to return the true query count (all_queries delta). The official
      code returns num_calls == 40 after only 39 is_adversarial calls at the 40-iteration cap
      (proposed_attack.py:145/:165), overshooting q_num by one and tripping
      assert self.all_queries == q_num (proposed_attack.py:252) on non_targeted images. The
      returned boundary point is unchanged. B3b T3: the trajectory is bit-identical to the
      unpatched run up to the crash iteration (nq_match=True, norms_match=True, cap_fix_log=1 on
      all 3 non_targeted rows; the 3 targeted rows are identical at every checkpoint).

Why this is not a deviation of the attack: B3b T3 proves the attack trajectory and the reported
pixel L2 are unchanged; only the returned query count (an internal counter) is corrected, and the
model object is put on the official path. The change is disclosed in the paper as
"accounting fix, trajectory unchanged".
